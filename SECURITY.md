# Security Policy

GestEase Technology Inc. takes security seriously. This document describes how to report vulnerabilities related to the GestEase Agent and outlines the security practices that govern this distribution.

---

## Reporting a vulnerability

If you discover a security issue in any released agent binary, in the `.cmd` installer generated by GestFlow, in the self-install flow (`agent.exe --install`), or in the interaction between the agent and the GestFlow backend, please disclose it responsibly.

**Contact:** `security@gestease.ca`

Please include:

- A clear description of the issue and its potential impact
- Steps to reproduce (if applicable)
- The agent version affected (visible via `Get-Service GestEaseAgent` and the install directory)
- Any proof-of-concept code, redacted as needed

### What to expect

| Milestone | Target SLA |
|-----------|-----------|
| Acknowledgement of report | Within 2 business days |
| Initial triage | Within 5 business days |
| Remediation for high-severity issues | Within 30 days |
| Public advisory (if applicable) | After fix is available in all supported releases |

We will coordinate disclosure timing with the reporter and credit researchers who request attribution, unless they prefer to remain anonymous.

**Please do not disclose security issues publicly before we have had a reasonable opportunity to investigate and remediate.** Public GitHub issues on this repository are disabled for this reason.

---

## Scope

### In scope

- `agent.exe` binaries published on the [Releases page](https://github.com/GestEase/gestease-agent-dist/releases)
- The `.cmd` installer script generated by the GestFlow web UI (any behavior exhibited during or after installation)
- The self-install flow triggered by `agent.exe --install` (Windows SCM registration, install directory setup, cloudflared download)
- The agent's local runtime behavior (file access, network calls, Windows service registration, subprocess management)
- Cryptographic flows: mTLS client certificate issuance, JWT validation, binding-code exchange, Cloudflare Tunnel provisioning

### Out of scope

- The GestFlow backend and web application (report via `security@gestease.ca` with clear indication; see the general [security disclosure policy](https://gestease.ca/security))
- Third-party dependencies bundled or downloaded by the agent (Cloudflare tunnel, Go runtime). Report these upstream; we will also relay to upstream maintainers when appropriate.
- Social-engineering attacks targeting GestEase customers or staff
- Physical security of customer infrastructure

---

## Safe harbor for good-faith research

Security researchers acting in good faith will not face legal action from GestEase Technology Inc. for:

- Accessing only their own organization's test data
- Making a genuine attempt to avoid privacy violations or service degradation
- Notifying us before any public disclosure, as described above

We ask researchers to refrain from:

- Running automated scans that generate disruptive load
- Accessing data belonging to other customers or organizations
- Modifying, deleting, or exfiltrating customer data
- Social-engineering our staff or customers

## Supply-chain practices

- Binaries published in this repository are built automatically by GitHub Actions from a private source repository maintained by GestEase Technology Inc.
- Build configuration uses pinned toolchain versions (Go, runner image) and pinned dependency checksums (`go.sum`).
- The full test suite must pass before a release is published.
- Release notes include a SHA-256 hash of `agent.exe`. See the [Verifying a binary](README.md#verifying-a-binary) section of the README for verification instructions.

### Roadmap

- **Authenticode code signing** of `agent.exe` (removes the "Publisher unknown" Windows SmartScreen warning)
- **SBOM** (Software Bill of Materials) attachment on each release
- **Supply-chain attestations** via Sigstore / SLSA
